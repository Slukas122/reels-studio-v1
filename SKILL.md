# Reels Studio

Create a **finished video that has been watched and heard**, with an editable project and a concise record of decisions. The default for supplied footage is a footage-led Reel; use designed animation only where it improves meaning or rhythm. When the brief itself is graphic, create a motion-only Reel. Default to one vertical 9:16 video in the source language. Preserve the user's exact creative choices and original files.

## Intake and creative direction

Extract the objective, audience, platform, source assets, exact required text, claims, CTA, brand rules, target length, music rights and references from the request and local files. Ask only for a missing source or decision that materially changes the result; otherwise use sensible defaults and record them. If the user asks to proceed directly, do not create a mandatory approval gate.

For recurring work, reuse an approved brand profile when one exists. Otherwise derive a temporary style sheet from supplied references and label inferred choices. If there is no brand evidence, use the adaptable, unbranded [default design system](references/default-brand.md). The preferred aesthetic is [minimal composition with energetic rhythm](references/minimal-rhythm.md): a few strong elements, beautiful timed captions, purposeful quick cuts and music that supports the edit. For recorded speech or action, default to a **native-looking Reel** with full-frame footage and selective motion. For a motion-only intro or ad, let typography and shapes carry the energy. Reserve designed full-screen motion in footage-led work for a real explanatory or structural need. Keep typography, palette, caption treatment, sound signature and motion behavior consistent across a series, while fitting the treatment to each topic. See [creative-system.md](references/creative-system.md) for the brief, beat sheet and review criteria.

Use the [platform-native playbook](references/platform-native-playbook.md) to select the opening, pacing, amount of graphics and ending by the viewer's job: expert explanation, real demonstration, situational meme, campaign or motion-only idea. It is based on observed examples and has explicit evidence limits. Apply its source-to-cut test for AI, technology and marketing work; never substitute a fixed cut interval or generic viral hook for the video's actual message.

Before selecting a format, transcribe the **complete** spoken source with the best available Whisper model, retain timecoded words, and inspect the full recording. Review uncertain names, numbers and negations by ear; a transcript is evidence to check, not a replacement for listening. Build the message map in [story-and-formats.md](references/story-and-formats.md): central idea, supporting ideas, evidence, causal links, indispensable context and what can be removed. Choose the format that can express that map honestly. Spoken excerpts, an editorial question followed by its actual answer, a demonstration, a reportage sequence, a hybrid, and a motion-only explainer or ad are distinct options. A source without speech needs visual and factual analysis instead of invented narration.

Choose the smallest capable production path:

| Source and result | Path |
|---|---|
| Existing speech or action footage where the story lives in the recording | Use the sibling `$reels-editor` skill at `../reels-editor/SKILL.md`. Its FFmpeg and Remotion paths handle selection, cuts, captions, crop, sound and QA. |
| Text, data, photos or real website screenshots where the story is designed as animation | Read [motion-path.md](references/motion-path.md), then use the installed `$motion-studio` engine and examples. |
| Footage plus substantial designed graphics, B-roll or motion sections | Lock the source edit with `$reels-editor` first. Build needed motion sections with `$motion-studio`; follow [hybrid-path.md](references/hybrid-path.md) to assemble and mix them. Check the final composed file. |

Do not send a talking-head edit through a frame-by-frame canvas renderer merely to add captions. Do not force recorded video into a motion template that cannot preserve its action or audio. For AI-generated product footage, use a dedicated generation workflow only when the user requests it; this skill handles the finished Reel and its review.

## Default cover image

For every finished Reel, create a cover that explains its actual topic while playback is stopped, unless the user opts out or supplies an approved cover. This also applies when production is routed through reels-editor or motion-studio; carry the cover requirement through assembly and delivery.

- Choose a sharp, flattering frame from the supplied footage: natural expression, open eyes and an identifiable person, product or action. For footage without a suitable portrait, use a relevant supplied asset or a topic-led graphic. Write a short, specific headline in the video's language that the content actually supports; do not default to a generic slogan.
- Match the approved caption typography, colors and highlight treatment. Keep the face and key subject unobscured, and make the headline readable at phone thumbnail size, including the intended feed/profile crop. Follow the user's current font preference; do not silently substitute another font. If generated typography cannot reproduce an exact font, use the real font in the editable text layer.
- Preserve the person's likeness. Use available image-generation/editing tools when appropriate, and disclose in the delivery/project notes whether the cover is an original frame with typography or an AI-edited/generated image. Do not describe an AI-edited portrait as an untouched screenshot. Respect requests to keep the original photo unaltered.
- Insert the cover as **exactly one first video frame** by default, not a multi-second intro: duration is `1 / output_fps` (about 0.033 s at 30 fps, not 0.01 s). Start the existing edit immediately afterward. Add no opening sound effect or music for the cover. Shift audio, captions and timeline events together by that one frame so no speech is clipped and synchronization is preserved.
- Export a standalone high-quality PNG or JPEG cover alongside the MP4 for explicit thumbnail selection when publishing. A first frame does not guarantee that every player or social platform will use it as its thumbnail. Preserve the cover asset and its source/provenance in the editable project.
- Verify the actual encoded first frame, immediate transition into the video, headline spelling and crop, one-frame duration, and audio/caption sync. Use consistent color handling so the cover and footage are not accidentally dimmed by repeated HDR/SDR conversions.

## Production loop

1. **Find the story before polishing.** Inspect the complete source media, full transcript and brief. Build the message map and select a format using [story-and-formats.md](references/story-and-formats.md) and the [platform-native playbook](references/platform-native-playbook.md). Choose one clear point and a truthful opening; map opening, development, proof or demonstration, and resolved ending. The hook must be understandable with sound off when possible and cannot overstate what the clip proves. Verify that its promised answer or event appears in the finished cut. For a demo, show the real interface and output long enough to read; for a dialogue, preserve the exchange; for a campaign, keep the product and offer identifiable. Keep a cut or visual change only when it helps comprehension or pace.
2. **Make a timed beat sheet.** For each beat record time, picture, on-screen words, spoken audio or music, motion and intended viewer takeaway. Mark important moments on musical beats when music is central. Use this as a working plan, not a mandatory user approval checkpoint.
3. **Create a rough preview early.** Prove narrative flow, crop and text density before expensive rendering or detailed effects. Fix a weak opening, missing context or false claim before polishing. Use real screenshots, supplied imagery and licensed audio; record provenance.
4. **Finish picture and sound together.** Give the main message visual priority and follow [minimal-rhythm.md](references/minimal-rhythm.md). After the single-frame cover, begin footage-led Reels with the actual person, action or result; avoid a multi-second title intro, compulsory boxed headline, lower third, map, counter, news-style panel or end card. Keep a strong spoken hook as speech when it already works. Add motion graphics only where they clarify a relationship, sequence, comparison, number or offer, or make a meaningful transition more legible; allow a strong face, gesture or demonstration to remain unobstructed. Before placing text or cropping a subject, use [platform-safe-zones.md](references/platform-safe-zones.md) to plan around the top navigation, right-side actions and bottom profile, caption and controls of **each** target placement, including TikTok, Instagram Reels and Facebook Reels when relevant. Check current platform guidance when available; overlay sizes vary by device and caption length. Let nonessential footage fill the frame; protect the actual bounds of key words and subjects instead of shrinking the entire picture. If one shared layout wastes space or obscures a key element on a platform, produce tailored layout/crop variants. Measure the rendered bounds of every card, label and caption using its final font, weight and longest copy; follow [text-fit.md](references/text-fit.md). Caption only audible words in spoken videos and align them to the final edited audio. Use music and SFX to support actions and meaning rather than at fixed intervals.
5. **Review and revise the actual output.** Inspect representative stills and fast transitions, then watch the final MP4 from start to finish with sound. Check opening, every cut or scene boundary, longest text, factual claims, crop, audio balance and ending. Compare the finished story with the message map: the main idea and necessary supporting ideas must survive, and editorial question cards must be answered by the following footage. **Before delivery, create an interface-mask preview from the final encoded MP4 and inspect the opening, longest text, each distinct layout and ending at phone size.** If a word, claim, logo, face or key action falls under a mask, change the layout or crop and re-export. Run technical media validation. Do not claim review based on a successful command alone. Apply the relevant path's detailed QA.
6. **Deliver.** Provide the final MP4, standalone cover image, editable project, captions or transcript when applicable, and a short note about choices, source assets, verification and any material limitation. Keep intermediate files out of the user's output directory.

## Hard boundaries

- A beat sheet, prompt or preview is not a finished Reel. If media generation is unavailable, state exactly what exists.
- Do not manufacture a quote, testimonial, interface, metric, performance claim or before-and-after result. Verify factual data used in graphics and mark demo data visibly.
- Use only user-provided, licensed or otherwise authorized external assets. Attribute or record sources in project notes.
- Keep source media untouched. Use a job directory for edits and renders.
- Give the user's current instructions priority over workflow defaults, especially when they already supplied style, duration or authorization to proceed.
